Smart Plant Monitoring System - Architecture Migration Specification
1. Objective

Refactor the current ESP32-based smart plant monitoring system with the following changes:

Hardware Changes

Replace:

Servo motor used for water valve control

With:

Relay-controlled 5V submersible water pump

Keep:

ESP32
Soil moisture sensor (YL-69)
Temperature sensor (LM35 or DHT11/DHT22)
Lighting LED
Heating LED
Communication Changes

Replace:

HTTP polling communication

With:

MQTT publish/subscribe communication

MQTT Broker:

Eclipse Mosquitto

Deployment:

Self-hosted Docker container
Backend Changes

Replace:

Simple HTTP API server

With:

Django Backend
MQTT Client Service
MongoDB Database
Realtime Dashboard

6. MQTT Topics
Telemetry Upload

Topic:

plant/device/{deviceId}/telemetry

Example:

{
  "deviceId": "esp32-001",
  "temperature": 29.4,
  "soilMoisture": 63,
  "timestamp": "2026-05-20T10:20:00Z"
}

Published every:

30 seconds
Device Status

Topic:

plant/device/{deviceId}/status

Example:

{
  "online": true,
  "pump": false,
  "light": true,
  "heater": false
}
Command Topic

Topic:

plant/device/{deviceId}/command

Example:

{
  "pump": true,
  "light": false,
  "heater": true
}

ESP32 subscribes to this topic.

7. ESP32 Tasks
Task 1

Sensor Collection

Interval:

10 seconds

Responsibilities:

Read temperature
Read soil moisture

Store locally.

Task 2

Telemetry Publisher

Interval:

30 seconds

Responsibilities:

Publish telemetry topic.

Task 3

Command Listener

Responsibilities:

Subscribe:

plant/device/+/command

Execute commands immediately.

Task 4

Heartbeat

Interval:

60 seconds

Publish:

online status

11. Automation Module

Responsibilities:

Process business rules.

Examples:

THEN enable pump
IF temperature < threshold
THEN enable heater
IF ambient light low
THEN enable light

Automation execution:

Server-side only

No automation logic inside ESP32.
